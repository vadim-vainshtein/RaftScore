# Database backups

Configure `raftscore.backup.pg-dump` to the absolute path of a trusted local PostgreSQL `pg_dump` executable compatible with the server. Configure `raftscore.backup.directory` to a private persistent directory on a filesystem supporting atomic directory moves; the default is `./backups`. The service account must be able to write there. Set `raftscore.backup.timeout` to a positive ISO-8601 duration (default `PT10M`). The datasource must use a simple `jdbc:postgresql://host:port/database` URL without query options. The configured database account must have permissions to dump the entire database and read Liquibase history. Protect the backup directory and process environment from untrusted local users: archives contain all database data and the child process receives the password in its environment.

`POST /api/backups`, `GET /api/backups` and `GET /api/backups/{id}/download` require FULL_ACCESS. POST uses normal CSRF protection. A published UUID directory contains a ZIP bundle and separate publication metadata. The bundle contains a PostgreSQL custom archive and a properties manifest with its SHA-256, size, format and Liquibase history fingerprint. The fingerprint hashes length-prefixed UTF-8 values of ID, author, filename and checksum ordered by Liquibase execution order, and is checked before and after dumping. This detects changes in recorded migrations, not untracked schema modifications. Archives are created using pg_dump's consistent snapshot; concurrent DDL or migration activity should be avoided. The download is a ZIP with fixed `manifest.properties` and `archive.dump` entries, retaining both for future restore validation. Restore is not implemented here.
