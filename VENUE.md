# Установка RaftScore на площадке (Windows)

Одна машина хранит данные и запускает сервер; остальные устройства открывают его в браузере по локальной сети. Проверьте установку и восстановление до соревнований. Пример ниже выполняется в PowerShell, из отдельной папки установки, не в каталоге действующего стенда.

## Подготовка до выезда

Нужны Windows с Docker Desktop и Compose, Java 25 или новее, клиентские программы PostgreSQL `pg_dump.exe` и `pg_restore.exe` версии 17 или новее, совместимые с PostgreSQL 17, и современный браузер. Подготовьте их установщики, образ `postgres:17-alpine` и готовый исполняемый JAR RaftScore заранее: при отсутствии интернета сборка исходников и загрузка образа невозможны. На машине с интернетом сохраните образ командой `docker save -o postgres-17-alpine.tar postgres:17-alpine`; на площадке загрузите `docker load -i postgres-17-alpine.tar`. Проверьте `docker compose version`, `java -version`, версии обеих утилит и запуск Docker Desktop. Для создания и восстановления копии предпочтительно использовать утилиты одной основной версии PostgreSQL; `pg_restore` на целевом экземпляре должен быть той же или более новой основной версии, чем `pg_dump`, создавший архив. JAR должен включать собранный интерфейс; его собирают из этой же версии исходников командой `mvn package` с установленными Maven, Node и зависимостями. Для автономной площадки перенесите уже готовый JAR, `compose.yaml` и это руководство. Не переносите рабочую базу как файлы Docker volume.

## Первый запуск

Создайте отдельную папку, положите в неё `compose.yaml` и JAR, переименованный в `raftscore.jar`. Откройте PowerShell в этой папке. Выберите свободные порты: в примере приложение использует 18080, а PostgreSQL доступен только на этом компьютере через 15440. Не используйте порты существующих установок. Пароли и ключ задаются оператором, не записывайте их в командную строку или историю. Сохраните их в защищённом хранилище: без ключа подписи перенос резервной копии невозможен.

```powershell
function Read-Secret([string]$prompt) {
  $secure = Read-Host $prompt -AsSecureString
  return [System.Net.NetworkCredential]::new('', $secure).Password
}
# Для нового рабочего экземпляра выберите уникальное имя; сохраните его для последующих запусков.
$env:COMPOSE_PROJECT_NAME = 'raftscore-venue'
$env:RAFT_SCORE_DATABASE_PORT = '15440'
$env:RAFT_SCORE_DATABASE_PASSWORD = Read-Secret 'Пароль новой базы'
$env:RAFT_SCORE_INITIAL_ADMINISTRATOR_PASSWORD = Read-Secret 'Пароль первого администратора'
$env:RAFTSCORE_BACKUP_SIGNING_KEY = Read-Secret 'Секретный ключ подписи резервных копий'
$env:RAFT_SCORE_INITIAL_ADMINISTRATOR_USERNAME = 'admin'
$env:RAFT_SCORE_DATABASE_URL = "jdbc:postgresql://127.0.0.1:$($env:RAFT_SCORE_DATABASE_PORT)/raftscore"
$env:RAFT_SCORE_DATABASE_USERNAME = 'raftscore'
$env:RAFT_SCORE_SERVER_ADDRESS = '0.0.0.0'
$env:RAFT_SCORE_SERVER_PORT = '18080'
$env:RAFTSCORE_BACKUP_DIRECTORY = (Join-Path (Get-Location) 'backups')
# Укажите реальные абсолютные пути к установленным утилитам:
$env:RAFTSCORE_BACKUP_PG_DUMP = 'C:\Program Files\PostgreSQL\18\bin\pg_dump.exe'
$env:RAFTSCORE_BACKUP_PG_RESTORE = 'C:\Program Files\PostgreSQL\18\bin\pg_restore.exe'
docker compose up -d --wait
if ($LASTEXITCODE -ne 0) { throw 'PostgreSQL не запущен' }
java -jar .\raftscore.jar
```

Не закрывайте окно с приложением во время работы. После сообщения `Started RaftScoreApplication` откройте `http://127.0.0.1:18080/`, войдите как `admin` с выбранным паролем. Первый администратор создаётся только при отсутствии активного пользователя с полным доступом; установка переменной позже не меняет его пароль. После остановки приложения Ctrl+C остановите базу командой `docker compose stop` (пока пароль ещё задан), проверьте успешное завершение команды, затем удалите секреты из окружения окна: `Remove-Item Env:RAFT_SCORE_DATABASE_PASSWORD, Env:RAFT_SCORE_INITIAL_ADMINISTRATOR_PASSWORD, Env:RAFTSCORE_BACKUP_SIGNING_KEY`. Для следующего запуска снова задайте те же параметры и секреты; bootstrap-пароль уже не нужен. `docker compose stop` останавливает базу без удаления данных; `docker compose up -d --wait` запускает её снова. Обе команды требуют заданного пароля базы и правильного `COMPOSE_PROJECT_NAME`. Не выполняйте `docker compose down -v` на рабочей базе.

PostgreSQL применяет пароль только при создании пустого тома. Для существующего тома используйте его действующий пароль: изменение переменной не меняет пароль в базе. При обновлении существующей Compose-установки сохраните её прежнее имя проекта (укажите его в `COMPOSE_PROJECT_NAME`) и том `raftscore-postgres-data`, укажите прежний пароль и используйте новый JAR после резервного копирования. Теперь Compose по умолчанию публикует порт 5432, как и ожидает приложение; для сохранения прежнего адреса базы явно задайте `RAFT_SCORE_DATABASE_PORT=5433` и соответствующий `RAFT_SCORE_DATABASE_URL`. Смена порта не меняет том, но проверьте, что выбранный порт свободен и настройки клиента совпадают. Если раньше использовался штатный пароль старой версии Compose, замените его отдельно штатными средствами PostgreSQL до работы на площадке. Не удаляйте том для исправления ошибки входа. Канонический локальный стенд имеет отдельные настройки и к этой инструкции не относится.

Перед созданием копии и перед проверкой восстановления выполните на соответствующем компьютере в окне, где заданы пути из примера выше:

```powershell
& $env:RAFTSCORE_BACKUP_PG_DUMP --version
& $env:RAFTSCORE_BACKUP_PG_RESTORE --version
```

Запишите основную версию `pg_dump` источника рядом с копией и сравните её с основной версией `pg_restore` цели: например, архив `pg_dump 18.x` требует `pg_restore 18.x` или новее, а `pg_restore 17.x` для него не подходит. Если версии не соответствуют этому правилу, установите подходящий клиент и укажите его абсолютный путь до запуска приложения. Проверяйте именно пути, заданные приложению, а не случайную утилиту из `PATH`.

## Второе устройство

Подключите оба устройства к одной доверенной локальной сети, узнайте IPv4 сервера через `ipconfig` и откройте на втором устройстве `http://<IPv4-сервера>:18080/`. Разрешите входящие TCP-подключения к выбранному порту приложения в брандмауэре только для доверенной сети; изоляция клиентов Wi-Fi может мешать соединению. Адрес `127.0.0.1` на втором устройстве указывает на него самого. PostgreSQL опубликован только на loopback сервера и не требует открытия порта для клиентов. HTTP в этой схеме не шифрует пароли и данные: используйте изолированную доверенную сеть или заранее настроенный HTTPS; не публикуйте сервис в интернет.

## Резервная копия и проверка восстановления

Войдите с полным доступом, откройте раздел резервных копий, создайте копию и скачайте ZIP на отдельный защищённый носитель. Храните отдельно ключ подписи и учётные данные: ZIP содержит данные соревнований и пользователей. Копируйте архив регулярно и перед обновлением; не меняйте его содержимое. Дождитесь окончания операций и избегайте внешних записей и изменений схемы БД при копировании и восстановлении.

Для проверки подготовьте **отдельную** папку установки с теми же версией JAR и схемой БД. В отдельном окне PowerShell выполните первый запуск по инструкции выше, но задайте явно другое уникальное имя проекта, например `raftscore-venue-restore`, вместо `raftscore-venue`, другие свободные порты, например 15441 для базы и 18081 для приложения, новый пароль базы и первого администратора и тот же ключ подписи, что на источнике. Имя проекта определяет том: не используйте имя рабочего проекта, даже если папки разные. До запуска убедитесь, что выбранного имени нет в `docker compose ls --all` и что выбранные порты свободны. Подставьте выбранные значения в команды первого запуска, включая URL базы.

Перед восстановлением проверьте фактический проект, том и привязку базы, а также порт приложения; выполните в окне проверочной установки с заданным паролем базы:

```powershell
docker compose config --quiet
if ($LASTEXITCODE -ne 0) { throw 'Ошибка конфигурации' }
$container = docker compose ps -q postgres
if ($LASTEXITCODE -ne 0 -or @($container).Count -ne 1 -or !$container) { throw 'Контейнер базы не найден или не единственный' }
docker inspect --format '{{ index .Config.Labels "com.docker.compose.project" }} {{range .Mounts}}{{.Name}} {{end}} {{json .NetworkSettings.Ports}}' $container
$listeners = @(Get-NetTCPConnection -State Listen -LocalPort 18081)
$listeners | Select-Object LocalAddress, LocalPort, OwningProcess
$listeners | ForEach-Object { Get-CimInstance Win32_Process -Filter "ProcessId=$($_.OwningProcess)" | Select-Object ProcessId, ExecutablePath, CommandLine }
```

Сопоставьте вывод с выбранными `raftscore-venue-restore`, томом `raftscore-venue-restore_raftscore-postgres-data` и `127.0.0.1:15441`; они должны отличаться от рабочего проекта и тома. Убедитесь по PID, пути Java и командной строке, что единственный слушатель 18081 принадлежит проверочному JAR из отдельной папки, и откройте именно `http://127.0.0.1:18081/`. При любом несовпадении остановитесь и выясните причину до восстановления. Полный вывод `docker compose config` содержит пароль базы, поэтому не сохраняйте и не передавайте его. Войдите в отдельный экземпляр его администратором, выберите загрузку ZIP в разделе резервных копий, подтвердите замену данных и введите текущий пароль этого администратора. Восстановление заменяет данные целевого экземпляра и завершает сеансы; после него войдите учётной записью из копии и проверьте соревнования и результаты. Оно требует единственного запущенного экземпляра приложения и совпадающей схемы; копии старого формата или с несовпадающим ключом не загрузятся. Не восстанавливайте проверочную копию поверх рабочего экземпляра.
